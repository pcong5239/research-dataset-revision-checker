How decentralized revision verification works

A four-stage consensus lifecycle for reviewing dataset provenance without relying on a single source.

01

Gather references

Identify the public dataset landing page, the authoritative repository, and the expected semantic version and license identifier.

02

Register & freeze

Connect your wallet, submit the bounded case parameters, and freeze the case to seal references against retroactive modification.

03

Consensus assessment

Trigger validators to read both remote sources. If an endpoint is temporarily unavailable, it remains unresolved for an explicit retry.

04

Cryptographic readback

Verify the SHA-256 evidence digests and final assessment outcome. Terminal states are confirmed before reporting success.

The contract stores bounded references and normalized evidence digests, not the source bodies. If a wallet request is cancelled or a network check is interrupted, the page explains the next safe action and never submits the same request automatically.
